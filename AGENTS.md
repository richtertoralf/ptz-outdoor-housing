# Verbindliche Arbeitsregeln

- Dokumentation, Issues und Pull Requests auf Deutsch verfassen.
- Jede Dokumentationsdatei auf eine Bildschirmseite begrenzen
  (Richtwert: 5–50 kurze Zeilen); nur der vollständige Lizenztext ist ausgenommen.
- Nur Informationen dokumentieren, die nicht unmittelbar aus Code, Parametern,
  Dateinamen oder Verzeichnisstruktur hervorgehen; keine Wiederholungen.
- Technische Erläuterungen vorrangig als Kommentare im CAD-Code pflegen.
- Geometrie, Parameter und CAD-Dateinamen nur bei ausdrücklichem Auftrag ändern.
- Weitere Kameramodelle in eigenen Ordnern unter `cameras/` führen.
- Keine vorsorglichen Platzhalter, leeren Ordner oder Konzeptdokumente anlegen.
- Architektur, Werkzeuge und Abhängigkeiten nur bei konkretem Bedarf ergänzen.
- Eigene CAD-Dateien CERN-OHL-S-2.0 zuordnen; den offiziellen Lizenztext erhalten.
- Bei reinen Verschiebungen CAD-Inhalte bytegenau mit dem Ausgangsstand vergleichen.
- CAD-Änderungen auf offensichtliche Widersprüche und betroffene Schnittstellen prüfen.
- Offene Konstruktionsprobleme bei Bedarf als Issues mit Problem, Ziel,
  gewünschtem Ergebnis, Rahmenbedingungen und überprüfbarer Abnahme erfassen;
  unnötige Implementierungsvorgaben vermeiden.
- Änderungen auf einem Branch bearbeiten und als Pull Request vorlegen.
